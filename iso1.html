Usuarios, grupos locales y permisos en Windows

Objetivo: planificar usuarios y grupos, crearlos en Windows de laboratorio y comprobar los permisos efectivos con pruebas reales.

1. Conceptos básicos

Una cuenta identifica a un usuario. Un grupo facilita asignar permisos de manera conjunta. La pertenencia a un grupo no implica automáticamente acceso a cualquier carpeta: hay que revisar permisos NTFS y, si existe recurso compartido, también permisos de uso compartido.

Trabaja con cuentas estándar. Usa administrador solo para tareas de configuración. En Windows, un permiso Denegar explícito puede prevalecer sobre concesiones; no lo uses salvo que sea imprescindible para la práctica.

2. Práctica guiada (máquina virtual Windows)

  1. Comprueba la edición de Windows. Si es Windows Home, algunas consolas de gestión como lusrmgr.msc pueden no estar disponibles; utiliza Configuración o net user y net localgroup.
  2. Diseña una tabla con dos usuarios estándar (usuario_a y usuario_b) y un grupo local (EquipoPracticas). No emplees nombres de alumnos reales.
  3. Abre una terminal elevada solo para la administración y crea el grupo: net localgroup EquipoPracticas /add.
  4. Crea las cuentas desde la gestión de usuarios de Windows o con net user usuario_a * /add y net user usuario_b * /add. Introduce contraseñas de laboratorio al solicitarlo; no las documentes ni fotografíes.
  5. Añade únicamente usuario_a al grupo: net localgroup EquipoPracticas usuario_a /add. Comprueba la composición del grupo con net localgroup EquipoPracticas.
  6. Crea C:\LaboratorioISO. Desde Propiedades → Seguridad → Opciones avanzadas, revisa la herencia. En una VM de pruebas, prepara una carpeta específica donde el grupo EquipoPracticas tenga permiso Modificar. Conserva el acceso del grupo Administradores y de SYSTEM; no cambies permisos de carpetas del sistema.
  7. Comprueba, iniciando sesión como cada usuario, si usuario_a puede crear y editar un fichero y si usuario_b no puede modificarlo. Antes de sacar conclusiones, comprueba si otros permisos heredados siguen concediendo acceso.
Atención: realiza los cambios exclusivamente dentro de la VM. No edites permisos de C:\Windows, C:\Users ni del equipo físico. No elimines las entradas de SYSTEM o Administradores ni te quedes sin una cuenta administrativa.

3. Evidencias y entrega

  1. Tabla de planificación de usuarios, grupos y permisos previstos.
  2. Captura de pertenencia al grupo (sin contraseñas).
  3. Captura de permisos NTFS de C:\LaboratorioISO.
  4. Tabla con pruebas de lectura, escritura y modificación para las dos cuentas, con explicación de los resultados.

Guarda las evidencias y un informe PDF en tu equipo. Cuando vuelva Aeducar se indicará dónde entregarlo.
